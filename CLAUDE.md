# Romantica Pizza POS

Web point-of-sale for Romantica Pizza (رومانتيكا بيتزا), a pizza restaurant in Syria. It runs on a mini PC inside the store and is built so it can later serve other restaurants without a rewrite. The full plan is in `docs/PLAN.md`, and decisions are in `docs/decisions/`.

The developer is in Calgary, 9 hours behind Damascus. Someone on site tests each milestone in the store.

## Stack

- TypeScript end to end, pnpm workspaces, Node 22, one repo.
- `apps/web`: React 19, Vite, Tailwind 4, i18next. It is an installable PWA used on tablets in Chrome.
- `apps/api`: Express 5, a REST API. WebSockets (Socket.IO) are added when the kitchen screen needs them.
- `apps/printer`: the print queue plus ESC/POS over raw TCP port 9100. Arabic is drawn as a raster image with @napi-rs/canvas and the bundled Cairo font.
- `packages/shared`: types, money math, tax rules and validation shared by every app.
- PostgreSQL 16 with Drizzle ORM. The schema is in `packages/db`, and migrations live in `db/migrations`, generated by drizzle-kit.
- Tests use Vitest for unit tests and Playwright for end-to-end tests.
- Apps run their TypeScript directly with `tsx` in both dev and production, so there is no build step except for `web`.
- Everything runs under Docker Compose. Images are built in Calgary and loaded on the store PC over Tailscale or USB, because nothing is downloaded in the store.

## Folder layout

```

apps/printer      print queue, ticket renderer, ESC/POS sender

docs/             PLAN.md, decisions/, runbooks, milestone plans
.githooks/        pre-commit runs type-check + tests
.claude/rules/    path-specific rules (e.g. printer)
```

## Commands

- `pnpm install` installs dependencies and turns on the git hooks.
- `pnpm dev` starts every app in watch mode. Postgres comes from `docker compose up postgres`.
- `pnpm check` runs the type-check and all tests. It must pass before every commit (the pre-commit hook and CI both enforce this).
- `docker compose up --build` starts the full system: web on :8080, api on :3000, plus printer and postgres.
- `pnpm db:generate` generates a migration from `packages/db/src/schema.ts`. Migrations are applied automatically when api or printer starts.
- Database tests run only when `TEST_DATABASE_URL` is set, for example `postgres://pos:test@localhost:55432/pos_test` against a throwaway Postgres container. CI always sets it.
- `pnpm --filter @pos/api menu:import [file.json]` re-imports a menu file. It is idempotent and logs every price that moved.
- `docker compose --profile dev up -d --build` (with `RECEIPT_PRINTER_HOST=fake-printer` in `.env`) followed by `pnpm --filter @pos/e2e e2e` runs the end-to-end tests. Printed tickets land in `printer-output/`.

## Non-negotiable rules

1. **Money is integer cents** of the new Syrian pound (SYP). Use the `Cents` type from `@pos/shared`. Never use floats, never use `toFixed` for math, and round only at defined points.
2. **Every table has `tenant_id`**, and every query filters by it. No query reads or writes across tenants.
3. **Orders are append-only.** A void, refund or edit creates an event row. Never `UPDATE` or `DELETE` order history.
4. **Print jobs go through the queue** (a jobs table in Postgres) with retry and backoff. Nothing sends to a printer directly, so a jammed or offline printer never loses a ticket.
5. **Arabic first, right to left.** Arabic is the default language and English is optional. Every UI string goes through i18next, and no hard-coded text appears in components. Use CSS logical properties (`ms-`, `me-`, `ps-`, `pe-`, `start`, `end`) and never `left` or `right`. Fonts are bundled, never loaded from the internet. Numerals are Western (123) for now and will become a setting later.
6. **Arabic on paper is always an image.** Tickets are rendered to a bitmap on the server and sent as an ESC/POS raster (`GS v 0`). Never send Arabic as printer text.
7. **Offline and power-safe.** The system works for a whole day without internet and recovers from sudden power loss. The API never depends on a cloud service to take an order.
8. **The order screen responds in under 200 ms** on a mid-range tablet.
9. **Tax rates, currency labels, the restaurant name and printer addresses are settings or `.env` values, never code.** Changing them never rewrites past orders.
10. **Secrets live only in `.env`, which is never committed.** Keep `.env.example` up to date when adding a variable. Staff PINs are hashed.
11. **Money-touching actions are audited** (who, what, when). Voids and refunds need a manager PIN.
